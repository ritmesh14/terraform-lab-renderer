# Lab 41 — Dynamic blocks

A `dynamic` block generates a repeated nested block from a list/map. Perfect for NSG
rules whose count and content you don't know at authoring time.

Here we build **one** NSG but feed it a variable list of rules. Add a rule to tfvars and
`terraform apply` extends the NSG without code changes.

## What it creates

| Terraform resource                  | Azure name                | Notes                                              |
| ----------------------------------- | ------------------------- | -------------------------------------------------- |
| `azurerm_resource_group.this`       | Resource group `rg-dynamic` | 1                                                |
| `azurerm_network_security_group.this` | NSG `nsg-dynamic`       | 1 NSG, **x2 `security_rule` blocks via `dynamic`** |

## Commands

```bash
cd 41-dynamic-blocks
terraform init
terraform plan
terraform apply
terraform output rule_names
terraform destroy
```

Override the rules, e.g. a third rule via CLI or tfvars:

```bash
terraform apply -var='rules=[{name="Allow-SSH",priority=220,port=22},{name="Allow-HTTP",priority=200,port=80},{name="Allow-HTTPS",priority=210,port=443}]'
```

## What to see in the Azure portal

- Resource group `rg-dynamic` → NSG `nsg-dynamic` → **Inbound security rules**:
  `Allow-HTTP` (TCP 80) and `Allow-HTTPS` (TCP 443), priorities 200/210 — exactly the
  entries of the `rules` variable, generated by the single `dynamic` block.

## Key concepts / gotchas

- `dynamic "security_rule"` + `for_each = var.rules` stamps out one nested
  `security_rule` block per list element — no code edits needed for a new rule.
- Inside the block, the label doubles as the iterator: `security_rule.value` is the
  current object (`security_rule.key` would be its list index).
- Nested attributes are set inside `content { }` — that inner block is the actual
  `security_rule` schema.
- `tostring(...)` again converts the numeric port to the string the provider wants.
- Dynamic blocks shine when rules come from input data; for a small fixed set, plain
  nested blocks are simpler and easier to read.
